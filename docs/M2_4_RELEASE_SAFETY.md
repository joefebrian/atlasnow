## Operator signature

The founder signs outside git. The private key stays on a machine the founder controls. It is not generated by an agent, not committed, not stored as a GitHub secret for this work, and not copied to the production VPS. Pull-request CI does not receive it.

The signed bytes are the canonical JSON of one approval statement, with these fields in this order:

- `schemaVersion` is `1`
- `purpose` is `atlasnow-migration-package-approval`
- `repository` is `joefebrian/atlasnow`
- `sourceSha` is the 40-character source commit
- `artifactDigest` is the SHA-256 of the packaged file list
- `inventoryDigest` is the SHA-256 of the applied and approved-pending names and SQL hashes
- `applied` is the sorted applied migration names
- `approvedPending` is the sorted pending names the founder has authorized
- `imageDigest` is `null`, or `sha256:` plus 64 hex characters when an image digest was measured separately

A missing field, an extra field, a different repository, or a reordered name list is rejected. A public key inside the statement or the artifact directory is rejected. The verifier uses the public key path the operator passes and the fingerprint in `scripts/release-trust-fingerprint.txt`. The artifact cannot choose its own key.

The committed fingerprint file contains the single word `UNPINNED`. The founder replaces that word later by computing SHA-256 over the SPKI DER of the public key on the machine that generated the key:

```sh
openssl genpkey -algorithm Ed25519 -out "$HOME/atlasnow-release-keys/signing.pem"
chmod 600 "$HOME/atlasnow-release-keys/signing.pem"
openssl pkey -in "$HOME/atlasnow-release-keys/signing.pem" -pubout -out "$HOME/atlasnow-release-keys/signing.pub.pem"
openssl pkey -pubin -in "$HOME/atlasnow-release-keys/signing.pub.pem" -outform DER | openssl dgst -sha256
```

Compare that digest to the one line in `scripts/release-trust-fingerprint.txt` before trusting it. A pull request that edits the line is not the comparison. These commands were not run for this change. No founder key exists in the repository.

Signing and checking, after the founder has created that key:

```sh
node scripts/release-artifact.mjs --manifest scripts/migration-manifest.json --source prisma/migrations --entrypoint deploy/docker-entrypoint.sh --out "$HOME/atlasnow-release-work/artifact"
node scripts/release-sign.mjs --private-key "$HOME/atlasnow-release-keys/signing.pem" --statement "$HOME/atlasnow-release-work/statement.json" --out "$HOME/atlasnow-release-work/approval.json"

```

`scripts/release-sign.mjs` refuses a private-key path inside this repository before it reads the file. `--git-sha` is not proof. The source SHA is `git rev-parse HEAD` of the checkout being checked, and it must equal the statement.

Tests use `generateKeyPairSync("ed25519")` in a temporary directory and delete it. A passing fixture signature is not a production release approval. `productionApproval` stays false while the fingerprint file is `UNPINNED` or the image extract is absent.

## Preflight

`node scripts/migration-preflight.mjs --manifest <file> --artifact <packaged-dir> --history <json-or-csv> --approval <file> --public-key <pem>`

The history file has `migration_name`, `checksum`, `started_at`, `finished_at`, `rolled_back_at`, and `applied_steps_count`. The program does not call Prisma.

It fails closed when the approval is missing, the signature does not verify, the public key fingerprint is not the independent pin, the repository or source SHA disagrees, the artifact or inventory digest disagrees, the entrypoint would migrate, a folder or checksum disagrees, a history row is missing, duplicated, unfinished, or rolled back, or a packaged folder is not in `applied` or `approvedPending`. `approvedGitSha` remains null, so this tree also fails with `UNPINNED_SHA`.

Exit 0 occurs only when `releaseDecision` is `GO`. `GO` requires a verified image extract. There is no extract, so this command exits 1. `packageGate: true` means the migration-package checks matched the supplied test pin. It is still NO-GO.
